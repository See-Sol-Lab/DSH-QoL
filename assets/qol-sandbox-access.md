The user also enabled "Automatically fix workspace sandbox access" in the DSH QoL Pack. When DSH starts, and within a few seconds after a workspace is added, the plugin gives the user Full control of each workspace folder (inherited by its contents), so the official sandbox's first grant succeeds on other drives such as D: or E:. If a newly added workspace still reports SetNamedSecurityInfoW / Win32 5 on grantWrite, the fix has probably not run yet: tell the user and suggest retrying the command in a few seconds, instead of changing permissions yourself.
